# Design

## Context

See proposal.md for motivation. Current `reports.py` combines document primitives/renderers with company, lines, fleet, cargo, annual and decision calculations. Seven specialized builders import those presentation primitives while computing their own business results. The current source already uses `report_policy.resolve_context`, the shared clock and endpoint-aware catalog calls in several places; this change must not repeat old nominal-age bugs or add a second policy registry.

Observed examples: bottlenecks `_observe/_track/_status/_severity` plus `_stock_blocks` compute recurrence and stock slope; expansion `_candidates/_score/_rank` owns greedy demand allocation while `_starved_blocks/_town_blocks` hide further diagnostics; lines-history `_classify/_vehicle_events` owns robust trend and change comparisons. `report_history` computes milestones and earnings-offset segments inside section functions. Industry chain/outlier/manual-review, town headroom/pair selection and ROI swap screens similarly mix analysis with document construction. Relevant regression suites already assert report-visible classes, score sums, shared demand, future-history exclusion, unknown flows, calendar ambiguity, cargo matching and adjacent chart/table numbers.

## Goals / Non-Goals

**Goals:** One owner for every existing report analytic calculation; independently serializable, useful results; preserved current algorithms and default report behavior; explicit finite public views; endpoint-bounded data access and honest evidence limits.

**Non-Goals:** A generic view registration framework, new policy schema/criteria, a stored materialized-view cache, presentation objects in evaluation, arbitrary queries, new forecasts or geometry, player-specific conventions, or recreating every legacy script page. Runtime store/library paths remain configuration, not checkout `data/` assets.

## Decisions

### D1. Extend the prerequisite operation, not its responsibilities

`separate-analysis-evaluation` supplies operation-scoped `Evaluation`, selected in-memory evidence/context and the stored-only read-only application operation. Preserve its serialized fields: version, snapshot, save, methodology, timeBasis, reportPolicy/engineThresholds, roles, ruleResults, complete findings/recommendations, disabledFindings and coverage (`skipped`, `unsupported`, `notEvaluable`). Add `analysisViews`, empty by default. Views never replace or truncate those base findings/recommendations. No Store or report object is serialized.

Extend `Companion.evaluate(..., views: tuple[str, ...] = ())` and the underlying evaluation request with the seven literal names `bottlenecks`, `expansion`, `lines-history`, `history`, `industries`, `vehicle-roi`, `towns`. CLI adds repeated `--view NAME`; MCP evaluate adds `views: list[str] | None`. Validate names before view reads; collapse duplicate names and serialize keys in the fixed order above. Omitted/empty selection does not load extended history. Do not introduce seven new tools or a generic plugin endpoint. Reports select their relevant view through the same operation, not through CLI/MCP. `analyse` retains ingest + evaluate + compose + publish and its existing bundle return contract.

### D2. Concrete domain access and typed values

Add `analysis_views/` with `models.py` and seven modules named `bottlenecks.py`, `expansion.py`, `lines_history.py`, `history.py`, `industries.py`, `vehicle_roi.py`, `towns.py`. Each exposes exactly `evaluate(evidence: <Family>Evidence, *, context: EvaluationContext) -> <Family>View`. The existing prerequisite context owns captured validated methodology, effective thresholds/policies, endpoint, save/scope and clock; do not recreate resolution here. Pure view functions receive immutable projections, not Store, report document, renderer or output directory. Application orchestration performs a closed explicit dispatch and prepares typed evidence; no registry/decorator/protocol plugin machinery.

Use frozen dataclasses with tuples for collections and a single serializer at the evaluation boundary. `AnalysisViews` has seven optional typed fields exposed through `evaluation.analysis_views.bottlenecks` etc.; serialized `analysisViews` omits unrequested fields. Every view has `coverage: ViewCoverage` with endpoint reference, sampled references, eligible/read/used counts, query/hydration limits, omitted counts, warnings, collection-error families and unavailable reasons. Shared methodology/time/policy provenance stays on the envelope; rows refer to sample ticks/entity `(kind,id)` and criteria keys rather than duplicating the full context.

Concrete result roots and required nested records:

| Result | Typed record collections / values |
|---|---|
| `BottlenecksView` | `BottleneckItem` (code, entity, observations, eligible, streak, status, severity, first/last flagged ticks, latest evidence), `StockRise` (stock identity, count/capacity points, slope, projected samples-to-full), `OccupancyPattern` (known sample count/mean/min/max/latest), station/depot group records, chronological `HealthPoint`, collector coverage |
| `ExpansionView` | `ExpansionCandidate` (typed producer/consumer/cargo refs, raw flows, distance with method/confidence, unmet/allocated volume, score components, penalty codes/amounts, rank, persistence numerator/denominator, alternatives), exclusion/dead-end records, proven-economics groups, `TownAnchorEstimate`, starved-input/town-demand records, `VehicleFitCandidate` and catalog reference |
| `LinesHistoryView` | `LineTrajectory` with typed `LinePoint`, early/recent medians, MAD, delta, all threshold terms/final threshold, maturity `TimeMeasure`, class/reason, sampled occupancy; `VehicleChangeEvent` before/after values, counts, verdict, profit-per-vehicle values; created/removed observations and `ManualFollowUp` |
| `HistoryView` | compact points, period closes/baselines, finance/network/traffic changes, turnover, growth/annualization, year-ago/year-end comparisons, gaps/cadence, extremes/milestones, earnings-offset segments and supported purchase-year cohorts |
| `IndustriesView` | complete/unknown flow records, all-industry and common-endpoint aggregates, lifecycle/level/production events, service by cargo/type and outliers, chain screens, stocks/closure exposure, inferred station-line links and manual-review records |
| `VehicleRoiView` | vehicle observations; carrier/model/cargo/age aggregates and ranks; same-line comparisons; historical group points; cargo mismatch and sampled-load fit screens; weak groups, swap candidates, ratios, verified-unit flags and unassessed reasons |
| `TownsView` | capacity/usage/demand rows and ranks; history aggregates; growth/stall records; station/passenger coverage; headroom gaps; demand-source links; pollution/noise relative hotspots; direct/transfer/disconnected town pairs; selected key observations |

`ManualFollowUp` and other diagnostic records hold stable reason/action codes, typed evidence and entity references. Human-readable explanation text may accompany them, but prose is not the only representation. Numeric ratios stay numbers, not formatted `x1.20`, arrows or Markdown; names remain untrusted display data. Unknown numeric results are null with stable reasons. No dataclass embeds arbitrary document blocks or a serialized raw Snapshot.

### D3. Full disposition matrix: no hidden analytical remainder

Every existing calculation belongs to one of the rows below. None is silently postponed or removed. Reuse existing `analysis.py` factual helpers underneath these owners rather than copy them.

| Existing location/calculation | Destination and disposition |
|---|---|
| Bottlenecks dedupe/observe/track, status/severity/noisy suppression, stock/full/unserved/rise, occupancy, station/depot groups, health counts/error family summaries | `BottlenecksView`; move calculations from section functions too. Keep stock slope in units/sample and extrapolation explicitly conditional. Priority family caps remain display selection, not erasure of results. |
| Expansion network/cargo matching, flow eligibility, already-served exclusions/dead ends, persistence/proven economics/stock fills/estimated anchors, downstream input usefulness, score/penalties/demand conservation, alternatives, catalog fit/capacity cross-check, starved industries/town demand | `ExpansionView`; preserve TOP_N=10 greedy selection and two alternatives as existing finite algorithm outputs. Selection affects later demand and is analytical, not a report row cap. |
| Lines-history collection/classify, occupancy statistics, best/worst metric order, vehicle-change medians/verdicts, observed creation/removal, follow-up priority | `LinesHistoryView`; keep removed lines distinct from current classes. Sparklines, display series sampling and table caps remain presentation over typed series. |
| History daily merge, adaptive period levels, period closes/deltas, turnover/traffic raw-counter differences, growth, YoY/year-end, cash/loan/network milestones and extrema, earnings-offset segments, purchase cohorts, cadence/missing periods/error summaries | `HistoryView`; preserve statistical/diagnostic tolerances and counter caveats; no earned-income inference. Chart point/cell/name truncation stays presentation. |
| Industries flatten/stats/common cohort, events/levels/movers, service by cargo/type/outliers, input/output chains, stock progression, closure timing/exposure, station-name inferred links, line exposure and manual-review selection | `IndustriesView`; keep ratios above one possible, missing-flow exclusion counts and inference confidence. Existing malformed-evidence section handling becomes structured unavailable subresults, not a renderer exception converted to a healthy result. |
| Vehicle ROI consist/cargo identity, maturity/aggregate returns, model/carrier/cargo/age groups, same-line comparisons, group trends, mismatch/size fit, weak-group swaps/catalog availability/raw ratios | `VehicleRoiView`; preserve consist/single-cargo restrictions, statistical minima, sample weighting, candidate limits and lack of causal/payback claims. Age bucket membership is derived grouping; bucket labels are presentation. |
| Town capacity/supply extraction, station/passenger graph, size/quantile ranks, growth/stall checks, weighted usage/coverage, usage-gap ordering, demand sources, relative hotspots and unlinked pairs/key findings | `TownsView`; preserve fixed current heuristics explicitly as engine-owned screens, not methodology policy or proven game failure. No station geometry or inferred town coordinates added. |
| `reports.py` company/modal/current/prior/year-ago differences and financial sample series | Internal `CompanyFacts` projection in analysis layer; reuse existing overview/modal helpers. No additional public view name. |
| `reports.py` lines ranking, loss/empty/stop-pair membership, finding joins/load trends | Internal `LinesFacts`; existing finding decisions come from endpoint evaluation. Report top/bottom nonoverlap and display limits stay presentation. |
| `reports.py` fleet losses/ages/retired models/depot capital/fleet-fit | Internal `FleetFacts`; reuse analysis fleet-fit and typed vehicle observations/catalog. Unknown asset values yield known subtotal plus coverage, not an invented complete total. |
| `reports.py` cargo full-stock/opportunity/closure screens | Internal `CargoFacts`; reuse existing factual/opportunity helpers with the operation's effective shared thresholds, including labels. Remove hard-coded 90% claims when criteria differ. |
| `reports.py` annual year/baseline/month coverage, closing/modal/line deltas, prior-year results, dated decisions and closing findings | Internal `AnnualFacts`; evidence selection and comparisons happen before composition. Explicit closing-endpoint evaluation provides policy findings; preserve closing rolling-level semantics. |
| `reports.py` decision entity resolution and before/after metrics/elapsed diagnostics | Internal `DecisionComparison`; retain ambiguity/missing/removed records, explicit bounded decision baseline and comparison endpoint; no automatic status changes or attribution of outcomes. |
| Methodology report verdict/role/support selection | Reuse prerequisite evaluation records; compose presentation only, never evaluate rules again. |
| All builders' headings, sections, wording, notes, number/date formatting, escaping, SVG/Markdown/HTML, chart styling, top/bottom display slicing and omission text | Remain report presentation; they consume typed numeric/order/diagnostic results. Formatting a delta is allowed; calculating a delta, selecting an outlier or a manual priority is not. |

The boundary is semantic, not a ban on arithmetic for SVG coordinates or pagination. Determining a chart's eligible numeric points can be a presentation choice only when it does not change analytical coverage or classification; reports must not replace unknown chart values with zero.

### D4. Preserve statistical safeguards and separate judgment from measurement

Reuse `methodology-report-policies` exact registry, ranges, defaults and origin maps. No new keys. Keep its engine-owned MIN_POINTS=5, MAX_K=6, 1.5-year line window switch, ROI MIN_SAMPLE=3/MIN_LOAD_SAMPLES=3, expansion proof/persistence minimum=3, stock-rise minimum three/max six and existing sampling/dedupe algorithms. Threshold terms combine exactly as today (relative change, noise multiplier, median-current floor); changing a methodology changes decision terms, not profit medians/MAD.

Unregistered current town quantile/headroom screens, history gap/earnings-offset heuristics and ROI weak-group loss-share/capacity-per-cost ordering remain fixed engine-owned algorithms with criteria disclosed in structured results. They are judgments, not physical facts, and not stealth additions to configurable policy. Documented game-mechanic caps/cargo matching are distinguished from those screens. Statistical minima protect evidence sufficiency; policy values express how strict a classification or preference is. Never let a policy override clock conversion, fabricate unknown inputs or waive hard sample guards.

Preserve default classifications, candidates, score parts and substantive ordering. Deliberate corrections are limited to future leakage, unknown-as-zero derived claims and stable tie-breaks. Capture each correction with a consumer-visible fixture and release note; do not opportunistically change formulas, repair units speculatively or rebrand hypotheses as recommendations. Full result lists retain eligible records beyond report display caps; fixed algorithm selection limits such as expansion TOP_N, town PAIR_POOL=10, ROI weak-group/candidate limits remain disclosed analytical scope.

### D5. Bounded evidence and history plans

Push endpoint/save predicates into SQL before ordering, grouping or limits. Compact projection iterators fetch batches of 256 eligible rows, never `company_history(limit=1_000_000)`/`2**31-1` followed by filtering. Preserve all eligible historical endpoints/line series needed by existing algorithms; a fixed read cap that silently truncates old history would change the algorithm. Streaming compact rows may visit the entire selected historical prefix; it is not constant-time or a promise of constant-size returned history. Compact JSON projection may parse one source row at a time where normalized storage lacks fields; never load all raw snapshots before discarding them. Add no stored derived data/schema migration merely for this extraction. Scope predicates and calendar ambiguity behavior come from prerequisite evidence selection.

| View | Eligible read and materialization plan |
|---|---|
| bottlenecks | Most recent 240 full snapshots at/before endpoint; existing near-simultaneous merge, last 36 persistence samples; quarterly trend representation at most 24 points; no extra hydration for charts. |
| expansion | Stream compact date/tick index; select at most 12 newest monthly and 8 older quarterly representatives plus endpoint (at most 21 distinct full samples), matching existing month logic; one latest catalog at/before endpoint. |
| lines-history | Stream endpoint-filtered date/tick and line-history projections, one retained tick per distinct date; all eligible line series compactly retained as needed; at most 12 full snapshots for occupancy plus selected endpoint. No N-per-line unbounded snapshot reads. |
| history | Stream compact company/network/entity-membership/vehicle-purchase projections for all eligible samples; daily merging/adaptive month-quarter-year periods and all consecutive events unchanged; hydrate selected endpoint only. Keep original source sample references and missing-date counts. |
| industries | Stream compact industry/flow/stock/error projections for all eligible samples; retain first/latest common-cohort facts, consecutive lifecycle events and stock progression; at most 14 evolution samples chosen with current rules. Full endpoint hydration only; historical calculations consume projections, not a list of raw Snapshots. |
| vehicle-roi | Stream compact sample index; existing monthly/quarterly group trend selection at most 8 historical samples, plus last 24 sampled-load snapshots and endpoint (union at most 33) and one endpoint-bounded catalog. Preserve current group trend algorithm and each historical sample's endpoint-bounded clock evidence. |
| towns | Stream compact town projections for all eligible samples and current station/line network; compute history/growth over eligible prefix, at most 40 evolution/chart representatives preserving first/latest; full endpoint only. |

Shared selected endpoint/catalog hydrations are operation-local reusable evidence, not persistent caches. Base report facts use existing 36-company/12-line/one-current windows and bounded calendar baselines; annual selects eligible year rows plus baseline/prior-year close through endpoint predicates, decision comparisons select only baseline/comparison snapshots and decisions recorded no later than comparison. Do not copy the base evaluation's short finding probe window onto every view. Expose count/read/sampling omissions accurately; public users cannot choose arbitrary SQL limits. Unknown/ambiguous temporal evidence yields explicit unavailable comparisons with current facts retained, not a guessed alternative timeline. No verified save isolation is promised.

### D6. Consumer migration and tests

Convert report builders to `build(view, *, presentation_context)` (or internal base-fact equivalents) and render entry points to receive an already evaluated operation. Remove Store-based analytical builder paths and their threshold/lens fallback resolution; migrate service, tests and direct internal callers together. A thin application-level report entry point may still accept a report request and explicitly obtain evaluation; it cannot live in the pure renderer as a second orchestration engine. Public report commands and `analyse` output/bundle behavior remain compatible. Markdown/HTML consume the same domain data; no renderer calls another renderer to discover facts.

Capture current neutral-default consumer-visible facts/ranks/classes/event dates, not exact prose or source text. Update the existing seven report suites, reports/calendar/threshold and methodology policy suites to assert view/report agreement. Add tests for nondefault policy effects, historical endpoint plus future retained catalog/entities, unknown evidence, deterministic ties, reused context provenance, no rendering on evaluate, no ingest/refresh, and read-only temporary database/file snapshots. Query tests check selected endpoint and hydration counts alongside result correctness, not private forwarding/source wiring. Boundaries are proven by numeric/membership outputs even if internal signatures later change.

## Risks / Trade-offs

- Extracting all existing report analytics is larger than moving three obvious functions, but leaving section-owned screening would perpetuate the second engine. The closed matrix makes scope finite.
- Compact all-history calculations remain proportional to eligible observations and may return long typed series. Streaming avoids an all-snapshot memory explosion without silently changing historical conclusions.
- Existing null handling can encode misleading totals; correct only explicit unknown-derived claims, retain known partial values with coverage and document expected differences.
- Some current heuristics are not methodology-configurable. Exposing their fixed criteria is honest; expanding the policy registry is a separate change.
- Concurrent prior policy/calendar/default work must land first. Rebase to those actual contracts instead of copying stale implementation notes. Existing historical outputs/player evidence remain untouched; rollback changes code, never rewrites user stores.
