# Proposal

## Why

The author-local generator under `data/analise/` duplicates product analysis, hard-codes a personal save path and naming policy, and mixes unsafe route inference and replacement arithmetic with presentation. After reusable evaluation and report analysis extraction, retaining it as a second implementation or permanent parity oracle would undermine a generic installed product.

## What Changes

- **BREAKING:** Remove exactly the seven executable legacy generator sources: `data/analise/{gerar,common,raio_x,evolucao,cidades,cadeias,frota}.py`; remove their generated bytecode caches, not player evidence or generated reports. Do not replace them with wrappers, a private generator or compatibility shims.
- Use an explicit preserve/already-covered/discard capability inventory, rather than five-page, wording, personal-name or algorithm parity. Preserve generic facts, diagnostics and methodology behavior through the package and the preceding changes.
- Require installed-wheel evaluation and report composition/publication to work outside the checkout with synthetic evidence and methodologies that contain no personal naming conventions. Package resources remain supported; optional runtime stores and imported methodology files remain supported configurable inputs.
- Replace the main methodology specification's author/source-parity requirement with a generic example and behavioral-boundary contract. Retain the existing packaged example bytes, identity, version and thresholds as optional policy, not an engine assumption. Document its 3.0 watch / 3.5 problem screening as a deliberate difference from the historical watch-only prototype, not measured congestion.
- Migrate active source references in README/contributor guidance and methodology/report documentation to supported package commands and self-contained examples. Preserve historical exports, archived decision/evidence records and playtest findings; migrate only actionable instructions that still prescribe the retired generator.

## Capabilities

### New Capabilities

- `distribution-independent-analysis`: supported analysis workflows run from an installed package without checkout-local code, policy or data assets and preserve player-owned data during retirement.

### Modified Capabilities

- `analysis-methodology`: replace the author-specific lossless source-parity requirement with generic declarative expressiveness and optional self-contained examples; boundary tests become independent of removed generator sources.

## Impact

Depends on `separate-analysis-evaluation` then `extract-report-analyses`: reusable operation-scoped factual/policy evaluation and extracted diagnostics/rankings/trends are prerequisites, not new engines in this change. Reuse `methodology-report-policies`, `consistent-game-year-accounting`, `validated-methodology-activation` and `user-methodology-default` for policy, clock, activation and selection semantics. No new policy registry, acquisition behavior or rendering implementation.

Affected areas: the seven local scripts and their caches; `openspec/specs/analysis-methodology/spec.md`; `docs/methodologies.md`, `docs/reports.md`, README and contributor guidance where applicable; optional-example behavioral tests and packaging integration coverage. The packaged example file remains unchanged. `data/analysis-rules.md` and `data/playtest-issues.md` remain evidence records, with only current generator instructions/source-reference migration if necessary. Archived proposals remain historical records, not operational dependencies.

Out of scope: deleting or rewriting snapshots, SQLite databases, preferences, configurations, notes, player methodology files or historical generated reports; blanket page parity; personal save/town/mode codes as product requirements; inferred cargo-chain graphs; speculative replacement payback; new station geometry or bridge changes; dashboards, plugins, network access, automated game actions, full save isolation and speculative accounting models. Removal does not wait for any of those features.
