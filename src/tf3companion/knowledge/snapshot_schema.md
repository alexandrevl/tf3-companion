# Snapshot data — schema v1

Generated by the `tf3_companion_bridge` mod in `<userdata>/towns_industries/tf3c_snap_<gameTime>.lua`, the only output sink, using `app.saveUserdata`. The game time in the filename is zero-padded to 15 digits. Refresh requests use `towns_industries/tf3c_request.lua`; the CLI is `tf3c` and the log prefix is `[tf3c]`. `gameTime` and `purchaseTime` retain raw internal ticks. `meta.yearDuration` is the nominal financial/query-duration ticks (`api.util.getDefaultYearDuration()`), not a calendar GAME-YEAR. Money uses game units. IDs identify game entities while they exist; they are reused after an entity is removed and can differ between machines (see "Identity and timing caveats"). Finding categories are `finance|lines|vehicles|industries|data`.

> **Evidence legend (imported research).** `MPF:<file>` cites a file of MPFever (https://github.com/dkdknight/MPFever, MIT, studied at commit `ae5fc96`; paths relative to its repository root). `[ADOPTED: observed|code|assumed|claim]` marks a fact taken on the MPFever author's word and not verified by this project; the class is the author's own: observed = measured by the author, code = read by the author in game code or the engine, assumed = the author's assumption, claim = stated without evidence. Every statement is paraphrased. `[INFERENCE]`, `[UNVERIFIED]` and `[DISCREPANCY]` keep their existing meaning.

The collector currently emits schema 1. The stored-evidence reader accepts additive schemas 1, 2 and 3
without rewriting their raw JSON or asserting that newer collector features have been game-validated.
Unknown later schema versions still require an upgrade; missing fields retain their normal unknown semantics.

## When it is generated

- On loading a save (the first frame with the mod active).
- Every 1/12 of a game year.
- When the companion requests it (`refresh`, or `tf3c refresh`, writes `towns_industries/tf3c_request.lua` with an `id`; the mod checks every 60 frames).

## Identity and timing caveats

Read these before joining snapshots over time or keying anything on an id.

- **Ids are reused after removal.** The engine hands out the ids of removed entities again, oldest freed first; only when none are free does a new entity take the next number. A vehicle or line id seen in an old snapshot can later name a different entity [ADOPTED: code] (MPF:native/mpfever_native.cpp:877-878; MPF:docs/RESEARCH.md:43). Measured on build 40420 by the author. Our own `line_history` and decision references key on ids, so an id match alone does not prove the same entity [INFERENCE]; confirm with the name and descriptors (station names on the stops, carrier, position) before trusting a join.
- **Ids come from one shared counter and depend on creation order.** The author reports that ids are never the same on two independently running games for anything created after the load, because each game's interface allocates entities the others never see (previews, store windows), so every later id can shift [ADOPTED: observed] (MPF:mod/mpfever_1/content/mpfever_refs.lua:1-13; MPF:mod/mpfever_1/content/mpfever_bridge.script.lua:13,1462-1464,4902). Ids that already exist in the save are the same everywhere [ADOPTED: code] (MPF:mod/mpfever_1/content/mpfever_refs.lua:420-425, approximate lines). Treat ids of things built or bought during a session as not comparable across machines or reloads [INFERENCE].
- **Cross-session descriptors the author uses instead of ids.** A construction is identified by file name plus position (matched within about 1 m); a depot or station by its construction plus its 1-based index in that construction; a road node by position; a station group by its first station [ADOPTED: code] (MPF:mod/mpfever_1/content/mpfever_refs.lua:62-140; MPF:mod/mpfever_1/content/mpfever_refs.lua:228-237). Vehicles and lines created in the live session have no such descriptor [ADOPTED: code] (MPF:mod/mpfever_1/content/mpfever_refs.lua:416-418).
- **Which game-time counter is exported.** The collector reads the `gameTime` field of the world's `GAME_TIME` component (see the fields table). The component also carries `timeOfDaySec`, `tickCount` and `updateCount` [ADOPTED: code] (MPF:mod/mpfever_1/content/mpfever_bridge.script.lua:149-152,3712-3713) and the author treats `gameTime` as advancing 200 units per simulation step at 1x [ADOPTED: assumed] (MPF:mod/mpfever_1/content/mpfever_bridge.script.lua:28). [UNVERIFIED] Whether `gameTime` counts milliseconds of game time, whether it stands still when the game is paused, and how it relates to `tickCount`/`updateCount` and to the game day (the day-length conflict is recorded in `mechanics`, M10). Check: compare consecutive `meta.gameTime` values of two monthly snapshots with `api.util.getDefaultMonthDuration()`, and read the other counters in one test snapshot.
- **String-keyed table order is not stable.** The game's Lua seeds its string hash from the clock and memory addresses, so `pairs()` over a table with string keys visits entries in a different order in every process and every launch [ADOPTED: observed] (MPF:docs/RESEARCH.md:66-70; MPF:docs/CHANGELOG.txt:400-407). Do not read list order of anything derived from such a table as meaningful; sort by id or name before comparing two snapshots [INFERENCE]. The game's own scripts for towns and industries iterate in that order, so growth decisions are not reproducible between launches either.
- **Component reads are transient.** A component returned by the engine is a view that is only valid until the next component read; copy the fields you need first. Struct members come back as copies, so writing a field of a nested value changes nothing [ADOPTED: claim] (MPF:mod/mpfever_1/content/mpfever_bridge.script.lua:5062-5063,7836). Entity ids can also dangle: an entity may be gone by the time its id is used, which the author guards with an existence check before use [ADOPTED: code] (MPF:mod/mpfever_1/content/mpfever_bridge.script.lua:5593,5652).
- **Failed reads are not free.** The author measured that each failed property read made the game write a crash dump and cost about 0.1 s even inside `pcall` (11 dumps per vehicle-part colour read) on the builds he used [ADOPTED: observed] (MPF:mod/mpfever_1/content/mpfever_common.lua:204-207; MPF:docs/CHANGELOG.txt:326-328). Do not probe unknown members in a loop.
- **Large integers.** Money can exceed 2^31 and the game's Lua 5.2 `%d` format rejects values above that, so serialise money with a floating-point format [ADOPTED: observed] (MPF:mod/mpfever_1/content/mpfever_common.lua:92-98; MPF:docs/CHANGELOG.txt:278-280).
- **Snapshot delay.** The interface half that runs the collector can lag the simulation by a few frames or steps, and a speed reading of 0 does not alone prove the world is still [ADOPTED: claim] (MPF:mod/mpfever_1/content/mpfever_bridge.script.lua:3690-3692,9655-9657). A snapshot is therefore an approximate instant, not an exact step [INFERENCE].
